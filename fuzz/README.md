# Native fuzz harness

`fuzz_jsonfuse.c` is a libFuzzer target over the real JsonFuse native core: Plan compilation, NDJSON framing, parsing, validation, filters, projection and the writer. It compiles the unmodified `src/jf_*.c` files against `shim/php.h`, a minimal fake of the Zend and PHP stream APIs, so no PHP process is involved.

```sh
fuzz/build.sh                    # needs clang with libFuzzer
fuzz/out/fuzz_jsonfuse fuzz/corpus/seed fuzz/corpus/regression   # replay
fuzz/run.sh 300 12               # 12 workers for 300 s each, then a coverage report
```

`guard_pages.c` (built by `fuzz/build.sh` as `guard_pages`, without sanitizers) runs the validating scan, `jf_scan_record`, with each record copied so that its four padding bytes end where a `PROT_NONE` page starts: one byte read past the padding faults, which ASan does not always see for the scan's 8-byte word loads. yyjson reads the same record on its own guard page; a record the scan accepts must be an object yyjson accepts with the same referenced values, a refused record must be unchanged, and the padding must hold what it held. `guard_pages <records> <seed>` generates records (cut anywhere, ending inside an escape, a UTF-8 sequence or a literal); `guard_pages -f <file>...` reads every line as a record. `.github/ci/sanitizer.sh` runs 200,000 generated records and the committed corpus.

Each input drives: a reference model, a clean run compared with that model byte for byte, a run with short reads and writes that must match the clean run exactly and, because its reads also count as fiber switches, must leave both stream flags set, and a fault-injected run (read and write failures, exceptions, a stream closed during a read, execution timeouts, a held stream, low `memory_limit`) that must fail safely with no leak, no leftover stream flag and only a prefix of the clean output.

Every exception is read through the real getters (`getReason()`, `getField()`, `getOption()`, the position getters, `getProgress()`) and its whole `getPrevious()` chain is checked:

- clean run: the reason code and `getField()` the reference model expects, the position, and progress; the output before the throw is exactly the records matched before the failure, and nothing is flushed;
- invalid plan: the first failure in compile order, with its reason, `getOption()` and `getField()`;
- fault run: the reason the fault calls for (`read_failed`, `no_data`, `write_failed`, `flush_failed`, `stream_closed`, `timeout`, `stream_in_use`, `memory_limit`, `counter_overflow`) unless the clean run's own failure comes first; a chain only where the write after a flushing failure failed, both carrying one position and progress; `bytesWritten` and `recordsEmitted` equal to what reached the output; progress equal to the reference over the input before the failure; for a flushing failure exactly those records written, and for `timeout` nothing written after the core saw the flag;
- `internal_error`: once per process, `Runner::process` on a `Plan` that was never compiled. The parser-pool `internal_error` is unreachable (yyjson refuses only pools below its minimum size, and the pool is always larger) and is not asserted;
- `counter_overflow` needs 2^63 bytes for real, so the counter fault lowers `ZEND_LONG_MAX`, a variable in the shim, for that one run;
- every fake stream call fails the oracle if an exception is pending, so the writer never runs with `EG(exception)` set.

Field specs and defaults. An input that starts with `FD` takes 3 bytes per field instead of 2, and one mode byte after the header; older inputs keep their meaning. The third byte picks a default from a table of every PHP kind at the default boundaries (ints at 2^53, 2^60 and 2^63 with their neighbours, `PHP_INT_MIN`, non-finite floats, strings of 1024 bytes that escape six-fold, 1025 bytes, invalid UTF-8, arrays), and the type byte's spare bits pick the spec form: the type string, `[type]`, `[type, default]` in either order, an unknown key (`Default`, `path`, `nullable`, an int key), a missing type, a type that is not a string, or the list form. The reference decides independently of `src/` which defaults a field admits (the int `float64` check on the significand, its own UTF-8 check) and what each emits, and the oracle checks:

- invalid plans: the first failure in compile order, keys before values (`unknown_option`, then `invalid_type`, then `invalid_value`), with `getOption()` and `getField()`;
- valid plans: a missing key emits the default, a present `null` never does, and output bytes match the reference;
- the writer bound: after compile, the plan's escaped-name and default totals equal the reference's own count, `jf_writer_init` gives exactly `prefixes + defaults + 40 * fields + 2` as the per-record overhead, and every output line is at most its record's length plus that overhead.

Limit mode (mode bit 0) builds 128 fields `f000` to `f127` with array specs: every default the 1024-byte string that escapes to 6,146 bytes, defaults of every kind on types that admit them, the same with some that do not, or long and escaped string defaults. Its body is cut after 8 lines, since one line can be 787 KB of output.

Field paths. An input that starts with `FP` takes 5 bytes per field: the three above, a path byte and a path seed. Array forms then carry a `path` of 1 to 8 segments from an eight-entry table (`a`, `b`, `c`, `id`, `x.y`, `0`, the empty key, `é`) picked by the seed alone, so fields that share a seed share a path and equal or strict-prefix paths are frequent; or one of eight invalid shapes (9 segments, empty, an int, `null` or array segment, a string key, a hole, a string); or a segment that is not UTF-8 or has 1025 bytes. The reference model walks every object reached through a plan path in document order, identifying a node by the first entry through it and its level, resolves paths by descending first occurrences, and decides the compile order (keys, type, path, default; then names and path conflicts entry by entry, the later entry named). The oracle checks `path_not_object`, `duplicate_key` at every level with its `getField()` and message, `invalid_path`, `invalid_name` and `duplicate_name`, and every nested output line against the writer's reservation, which paths do not change. The FP limit mode builds 128 fields of 8-segment paths (a binary tree of 382 nodes, one shared 7-segment prefix, 1,024 distinct nodes, or a late strict prefix that compile must refuse) and puts one record holding every path in front of the body, with a seeded duplicate, `null` intermediate or missing key at any level.

Where entries. An input that starts with `FW` keeps the FP field layout, takes the where count (0 to 17) from the mode byte, two record-seed bytes after it, and 10 bytes per where entry (`build_where9`; `make_seeds.py` writes them by name). An entry is the scalar shorthand, `=`, a number or string range of 1 to 4 bounds in any of their 24 orders, `in` of 1 to 256 elements of mixed kinds with duplicates, `=` or `in` with a range, `=` with `in`, all six operators, number and string bounds mixed (also with an `in` of up to 257 elements), or one invalid form for each plan reason an entry can raise: an unknown key (`==`, `IN`, `Path`, ` >`, `paths`, an int key) at any position, no operator, a `=` value, shorthand or bound that is NaN, INF, an array, bad UTF-8 or 1025 bytes (bounds also bool and null), an `in` that is not an array, empty, not a list or of 257 elements, a bad element, a name that is not UTF-8, the FP path shapes, and a valid entry with one operand broken. Operands come from tables at the range boundaries: 0, -0.0, 2^53 and 2^53 + 1, `INT64_MAX`, `INT64_MIN`, 2^63 and 2^64 as floats, 5e-324, 1e308, strings sharing prefixes, bytes above 0x7F, 1024 and 1025 bytes. An optional `path`, before or after the operators, takes 1 to 8 segments from the FP table, so where paths share prefixes with field paths and with each other; a 17th entry gives `too_many`. Up to 7 generated records go in front of the body: nested objects along every plan path, leaves drawn from the entry's own operands and their neighbours (an int plus or minus 1, the next double, a string one byte shorter or longer) or from a table of every JSON kind (integers near 2^53, 2^63 and 2^64, reals such as `9007199254740993.0` and `1.8446744073709552e19`, `-0.0`, `1e-400`, RAW numbers such as `18446744073709551616` and `1e400`, strings raw and escaped, surrogate pairs), a leaf shared with a field drawn to fit its type, and at most one mutation per record: a duplicate key (also escaped), a `null`, non-object or container value, a missing key, an unreferenced duplicate.

The reference decides independently of `src/`: the compile order inside an entry (keys, then the path, then the operands in declared order, for `in` the list check before the count before the elements, and last that an operator is present and that the range bounds are of one kind, so a 257-element `in` wins over mixed bounds), and matching by exact value, integers by sign and magnitude, an integer against a real through the real's exact `frexp` decomposition, never a conversion to double, strings as unsigned bytes with the shorter first on a common prefix. The oracle checks the first plan failure with `getOption()` and `getField()` (null for `too_many` and `invalid_name`), steps 6 and 7 for every entry in declared order after all fields (`path_not_object` and `where_not_scalar` with where paths, a missing leaf or intermediate never matching, defaults never seen), `duplicate_key` owned by a where entry, and the output bytes of every matched record. The FW limit mode builds 16 entries of 8-segment paths, distinct or sharing a 7-segment prefix, each with all six operators, 256 `in` elements and 1024-byte string operands (with mode bit 2 the odd entries take numbers around 2^53 + 1 that no double holds), 1 or 128 fields (1,152 path nodes), and two records: one that matches and one whose leaf for one entry holds for `>` and `>=` but fails the `=` after them.

Not covered, because they need real PHP: Zend bailout, real stream wrappers and filters, and fibers. Those are tested with PHPT. Also not covered: real `memory_limit` and ZendMM (the shim fakes the limit). Outside limit mode the generated plans are limited to 6 fields, drawn from fixed name tables, against a public limit of 128; the limit modes reach 128 fields, 16 `where` entries, 256 `in` elements and 8-segment paths. Record caps stop at 1 MiB. The reference model shares yyjson with the code under test, so a yyjson bug would not be caught by comparing the two.

`corpus/seed/` is generated by `make_seeds.py`. `corpus/regression/` holds a reduced set of inputs from fuzz runs; replay it after any native change.
